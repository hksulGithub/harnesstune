# Plan 16-01: Fleet Data Layer

## Goal

Create the `FleetDataProvider` abstraction (D-05), two implementations (`LocalFleetProvider` reading `~/.harnesstune/cron-runs/*.json`, `RemoteFleetProvider` wrapping `RelayClient`), fleet-specific TypeScript types, and extend the Dashboard message protocol to support fleet data flow between extension host and webview.

## must_haves

- FleetDataProvider interface with `getWorkspaceSummaries(days)`, `getAgentSummaries(workspaceId, days)`, `getAgentRuns(workspaceId, agentId, days)` methods
- LocalFleetProvider reads `~/.harnesstune/cron-runs/*.json` files, filters by date range, aggregates per-agent and per-workspace
- RemoteFleetProvider wraps RelayClient `getSummary()` and `getRuns()` methods
- Fleet TypeScript types: `FleetWorkspaceSummary`, `FleetAgentSummary`, `FleetRunRecord`, `FleetCostSummary`, `HealthState`, `CostTrend`
- Message protocol extended with `fleet:*` message types for webview communication
- DashboardPanel updated to handle `fleet:requestFleetOverview`, `fleet:requestWorkspaceDetail`, `fleet:requestAgentDetail` from webview

<threat_model>
## Threat Model (ASVS L1)

| # | Threat | Severity | Mitigation |
|---|--------|----------|------------|
| 1 | LocalFleetProvider path traversal via crafted agentName in CronRunFile | Medium | LocalFleetProvider reads only from `~/.harnesstune/cron-runs/` directory using `fs.readdir` — never constructs paths from user-supplied input. File paths come from directory listing, not query parameters. |
| 2 | Remote relay data injection via malicious relay server | Low | RemoteFleetProvider passes relay data through typed interfaces (AgentSummary, RunRecord) with known fields. No eval, no HTML rendering of raw relay data in extension host. Webview rendering is in Plan 02 which applies textContent only. |
| 3 | Denial of service via large local directory | Low | LocalFleetProvider filters files by date range (mtime check before JSON parse), bounding the number of files processed. No unbounded memory allocation. |
| 4 | Message spoofing from webview | Low | WebviewToHostMessage is typed union — switch/case handles only known types. Unknown types are ignored. postMessage origin is the webview's own iframe, enforced by VSCode. |
</threat_model>

<task id="16-01-02">
<title>LocalFleetProvider — reads ~/.harnesstune/cron-runs/*.json</title>
<read_first>
- src/types/fleet.ts (fleet types from task 16-01-01)
- src/providers/FleetDataProvider.ts (interface from task 16-01-01)
- packages/harnesstune-collector/src/plugins/claude-code/types.ts (CronRunFile: agentName, command, exitCode, startedAt, finishedAt, durationMs, outputTail)
- src/types/workspace.ts (WorkspaceRecord, IWorkspaceRegistry)
</read_first>
<action>
Create `src/providers/LocalFleetProvider.ts` implementing `FleetDataProvider`:

1. Constructor takes `IWorkspaceRegistry` to get workspace list.
2. `getWorkspaceSummaries(days)`:
   - For each local workspace, scan `~/.harnesstune/cron-runs/*.json` using `fs.promises.readdir` + `fs.promises.readFile`.
   - Parse each JSON file as `CronRunFile`.
   - Filter by `startedAt` >= `now - days * 86400000`.
   - Group by `agentName` to count unique agents.
   - Compute `errorRatePct` = (files with `exitCode !== 0` / total files) * 100.
   - Compute `health` using `computeHealth()` helper (see below).
   - Compute `lastActivityTs` from max `finishedAt` timestamp.
   - Return `FleetWorkspaceSummary[]`.

3. `getWorkspaceDetail(workspaceId, days)`:
   - Same file scan + date filter.
   - Group runs by `agentName`.
   - Per agent: compute `successRatePct`, `lastRunTs`, `costUsd` (0 if no costCents in CronRunFile), `costTrend` ('flat' for local — no previous period data in v1), `health`.
   - Aggregate workspace cost: sum of all agent costs, trend 'flat'.
   - Return `FleetWorkspaceDetail`.

4. `getAgentDetail(workspaceId, agentId, days)`:
   - Same file scan, filter by `agentName === agentId` and date range.
   - Map each `CronRunFile` to `FleetRunRecord`: `runId` = filename (without .json), `timestampTs` = Date.parse(startedAt), `durationMs`, `status` = exitCode === 0 ? 'healthy' : 'failing', `costUsd` = 0, `logText` = outputTail ?? ''.
   - Sort by timestampTs descending (newest first).
   - Aggregate cost: totalCostUsd = 0, totalTokens = 0, trend = 'flat'.
   - Return `FleetAgentDetail`.

5. Helper `computeHealth(runs: { exitCode: number; startedAt: string }[]): HealthState`:
   - If runs.length === 0, return 'no-data'.
   - Sort by startedAt descending.
   - If all runs exitCode === 0, return 'healthy'.
   - Count consecutive failures from most recent: if >= 3, return 'failing'.
   - Otherwise return 'degraded'.

Use `os.homedir()` + `/.harnesstune/cron-runs/` as the base directory. Wrap the entire readdir/readFile in try/catch — return empty arrays on ENOENT (directory doesn't exist yet).
</action>

<task id="16-01-03">
<title>RemoteFleetProvider — wraps RelayClient for remote workspaces</title>
<read_first>
- src/types/fleet.ts (fleet types from task 16-01-01)
- src/providers/FleetDataProvider.ts (interface from task 16-01-01)
- src/relay/RelayClient.ts (RelayClient class, getSummary, getRuns, getAgents methods, AgentSummary, RunRecord, ChannelSummaryResponse types)
- src/types/workspace.ts (WorkspaceRecord)
</read_first>
<action>
Create `src/providers/RemoteFleetProvider.ts` implementing `FleetDataProvider`:

1. Constructor takes a `Map<string, RelayClient>` — one RelayClient per remote workspace ID (keyed by workspaceId), and `IWorkspaceRegistry` for workspace metadata.

2. `getWorkspaceSummaries(days)`:
   - For each remote workspace in the registry (mode === 'remote'), get its RelayClient.
   - Call `relayClient.getSummary(days)` → `ChannelSummaryResponse`.
   - Map `ChannelSummaryResponse.agents` to compute aggregate:
     - `agentCount` = agents.length
     - `errorRatePct` = (sum of failureCount / sum of totalRuns) * 100, or 0 if no runs
     - `health` = `computeHealthFromAgentSummaries(agents)` (see below)
     - `lastActivityTs` = max of all agents' `lastRunAt` (parsed to ms), or 0
     - `platform` = workspace name from registry, or 'Remote'
   - Wrap in try/catch per workspace — return `health: 'no-data'` on error.

3. `getWorkspaceDetail(workspaceId, days)`:
   - Call `relayClient.getSummary(days)` + `relayClient.getAgents()`.
   - Map each `AgentSummary` to `FleetAgentSummary`:
     - `id` = agentSummary.agentId
     - `name` = matched AgentIdentity.name ?? agentSummary.agentId
     - `health` = computeHealthFromSummary(agentSummary)
     - `successRatePct` = agentSummary.successRate * 100
     - `lastRunTs` = Date.parse(agentSummary.lastRunAt) or 0
     - `costUsd` = agentSummary.totalCostCents / 100
     - `costTrend` = 'flat' (no previous period data from summary endpoint in v1)
   - Aggregate workspace cost: sum of all agent costs in USD.

4. `getAgentDetail(workspaceId, agentId, days)`:
   - Call `relayClient.getRuns(agentId)`.
   - Filter runs where `startedAt` >= `now - days * 86400000`.
   - Map each `RunRecord` to `FleetRunRecord`:
     - `runId` = run.id
     - `timestampTs` = Date.parse(run.startedAt)
     - `durationMs` = run.durationMs
     - `status` = mapRunStatus(run.status) — 'success'→'healthy', 'failure'→'failing', 'timeout'→'failing', 'running'→'healthy'
     - `costUsd` = (run.costCents ?? 0) / 100
     - `logText` = run.logExcerpt ?? run.errorSummary ?? ''
   - Sort by timestampTs descending.
   - Aggregate cost.

5. Helper `computeHealthFromSummary(a: AgentSummary): HealthState`:
   - If totalRuns === 0, return 'no-data'.
   - If failureCount === 0, return 'healthy'.
   - If successRate < 0.5, return 'failing'.
   - Otherwise return 'degraded'.

6. Helper `computeHealthFromAgentSummaries(agents: AgentSummary[]): HealthState`:
   - If any agent is 'failing', return 'failing'.
   - If any agent is 'degraded', return 'degraded'.
   - If all agents are 'no-data', return 'no-data'.
   - Otherwise return 'healthy'.
</action>
