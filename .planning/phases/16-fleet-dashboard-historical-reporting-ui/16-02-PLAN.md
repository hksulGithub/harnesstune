# Plan 16-02: Fleet Dashboard UI

## Goal

Rewrite the Dashboard webview from a live-session viewer into a fleet-first panel with three drill-down levels (Fleet Overview, Workspace Drill-Down, Agent Detail), breadcrumb navigation, date range selector, health indicators, cost summaries, and run history table with expandable logs. All copy, spacing, colors, and component specs per 16-UI-SPEC.md.

## must_haves

- Fleet Overview (Level 0) renders workspace cards with health dot, agent count, error rate, last activity, "View agents" CTA
- Workspace Drill-Down (Level 1) renders agent rows with health dot, success rate, last run, cost + trend arrow
- Agent Detail (Level 2) renders run history table with Timestamp, Duration, Status, Cost, expand toggle columns
- DateRangeSelector with "24h" / "3d" / "7d" / "30d" tabs, default "7d", state at root level (D-04)
- BreadcrumbBar with "Fleet > Workspace > Agent" navigation (D-03)
- HealthDot reusable 8px circle with 4 health states and correct VSCode CSS variable colors
- CostSummaryBar with total cost, trend arrow (unicode), token count
- RunLogExpander with pre-wrapped log text, max-height 200px
- Empty states and error states with exact copy from UI-SPEC
- All colors are VSCode CSS custom properties (no hex values)
- fleet.css uses spacing scale from UI-SPEC (xs=4px, sm=8px, md=12px, lg=16px, xl=24px)

<threat_model>
## Threat Model (ASVS L1)

| # | Threat | Severity | Mitigation |
|---|--------|----------|------------|
| 1 | XSS via log text rendered in RunLogExpander | Medium | Log text is rendered as React textContent (not dangerouslySetInnerHTML). React auto-escapes all string content in JSX. The `logText` field is displayed inside a `<pre>` element via `{logText}` expression — no HTML parsing. |
| 2 | XSS via workspace/agent names in breadcrumb or card | Low | All names rendered via JSX text expressions `{name}` — React auto-escapes. No innerHTML anywhere in the component tree. |
| 3 | CSS injection via VSCode CSS custom properties | None | All CSS variables reference VSCode's own theme variables. No user-supplied CSS values. fleet.css is static, bundled at build time. |
| 4 | Clickjacking via webview iframe | None | VSCode webview iframes have sandboxing enforced by the VSCode runtime. CSP in DashboardPanel.ts restricts script-src to nonce-only. |
</threat_model>

}
