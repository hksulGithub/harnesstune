<threat_model>
## Security Considerations

1. **Localhost-only binding (CCAD-01, D-03):** HookServer MUST bind to `127.0.0.1`, never `0.0.0.0`. This prevents remote machines from sending fake hook events.
2. **Session token validation (D-03):** Every request must include a valid `?token=` query parameter matching the randomly generated session token. Reject with 401 otherwise.
3. **Token generation:** Use `crypto.randomBytes(16).toString('hex')` — never `Math.random()`.
4. **settings.json atomic writes (D-08):** Write to temp file + `fs.renameSync` to prevent partial-write corruption. Create backup before first write.
5. **Input validation on hook payloads:** Parse JSON in try/catch. Ignore malformed payloads silently (do not crash the server).
6. **No Node.js imports in webview:** esbuild dual-target config prevents `fs`, `http`, `os` from leaking into browser bundles.
</threat_model>

**Create `src/server/HookServer.ts`:**
- Class extends Node.js `EventEmitter`
- Constructor takes `storageUri: { fsPath: string }`, generates `crypto.randomBytes(16).toString('hex')` token
- `start()`: returns `Promise<number>` (port). Calls `this.server.listen(0, '127.0.0.1', callback)`. Writes port to `{storageUri.fsPath}/hook-server.port`.
- `get hookUrl()`: returns `http://127.0.0.1:${this.port}/hook?token=${this.token}`
- `handleRequest()`:
  1. Parse URL, validate `?token=` matches `this.token`. If not, `res.writeHead(401).end(); return;`
  2. For all events: respond `200 {"continue": true}` immediately
  3. Buffer body via `req.on('data')` / `req.on('end')`
  4. Parse JSON in try/catch, emit `'hookEvent'` with parsed payload
  5. EXCEPTION: If `req.url` path contains event type info OR body indicates PreToolUse, the pause gate check happens BEFORE response. But since the body isn't available yet at response time, the architecture uses a two-phase approach: read URL path for event hint if available, otherwise buffer body first then respond. For simplicity in v1: buffer body in 'end' handler, THEN check pause state and respond. Body is <10KB so this is sub-millisecond. The HookServer exposes a `setPauseChecker(fn: (sessionId: string) => boolean)` method. If PreToolUse and checker returns true, respond with deny payload instead.
  6. Actually, revise: read full body FIRST (it's tiny), THEN respond based on event type. This is still well within the 5s timeout.
- `dispose()`: calls `this.server.close()`
- Create `src/server/index.ts` re-exporting HookServer

**Create `src/adapters/ClaudeCodeHookAdapter.ts`:**
- Class implements `AgentBackendAdapter` interface
- Private fields: `hookServer: HookServer`, `settingsPath: string` (resolved via `os.homedir() + '/.claude/settings.json'`)

- `injectHooks(hookUrl)`: Read `~/.claude/settings.json`, backup if first write, deep merge hook entries tagged `{ type: 'http', url: hookUrl, timeout: 4, _harnesstune: true }` into each event's array. - `normalizeEvent(workspaceId, raw)`: Map raw hook payload to `AgentEvent`.
